# 대화 중 내 AI 초대 — 조사와 화면 제안

조사일: 2026-09-08 · 코드 기준: `dfd590c` · 상태: **제품 흐름 제안 / 운영 미반영**

## 출발점

감독의 우선순위는 “간단한 AI 연결”이며, 구체적인 요구는
**“대화하다가 AI가 필요하면 버튼 하나로 AI를 초대”**하는 것이다.
각자 연결한 AI가 사람들과 같은 대화에서 맥락과 자료를 읽고 조사·판단·답변한다.
조직 계층과 영상통화는 범위 밖이다. 모바일 출시보다 이 핵심 흐름의 사용성을 먼저 확인한다.

이번 조사는 공식 제품 문서와 현재 코드 비교다. 다른 사용자 인터뷰나 경쟁 앱의
실계정 사용성 실험을 수행한 것은 아니다. 아래의 제품 제안과 수치는 검증할 가설이다.

## 공식 제품에서 확인한 흐름

| 조사 대상 | 확인한 사실 | Deuce에 적용할 제안 |
|---|---|---|
| Teams | 그룹 대화 상단에서 사람·에이전트 추가 → 에이전트 선택 → 기능·권한 확인 → 추가. [공식 안내](https://support.microsoft.com/en-us/teams/chat-channels/find-and-add-copilot-agents-to-group-chats-in-microsoft-teams) | AI 초대의 입구를 현재 대화 헤더에 둔다. 내 기본 AI가 정해져 있으면 매번 선택창을 띄우지 않는다. |
| Slack | 에이전트 앱 설치 후 접근 가능한 사용자가 대화를 시작할 수 있다. 채널에 추가하고 멘션해 요청한다. [공식 안내](https://slack.com/help/articles/33076000248851-Work-with-AI-agents-in-Slack) | 최초 연결과 일상적인 방 초대를 분리한다. 답변은 참여자 모두가 볼 수 있는 AI 신원으로 게시한다. |
| Teams 대화 목록 | 안 읽음·채팅·채널 필터와 멘션 빠른 보기를 제공한다. [공식 안내](https://support.microsoft.com/en-us/teams/teams-channels/explore-the-new-chat-and-channels-experience-in-microsoft-teams) | 목록을 유지하면서 필요한 방으로 빨리 이동하게 한다. 모바일에서는 목록과 대화를 한 화면씩 보여준다. |
| Slack 이벤트 | 가입한 앱에 대한 멘션을 `app_mention` 이벤트로 전달한다. 초대를 수반하는 멘션도 전달된다. [개발 문서](https://docs.slack.dev/reference/events/app_mention/) | 방 접근 권한 외에 요청을 실행기에 전달하는 경로가 필요하다는 참고 사례다. Slack API를 Deuce에 도입한다는 뜻은 아니다. |
| Codex | 원격 HTTP MCP, Bearer/OAuth 인증, 설정 파일·CLI·UI 등록을 지원한다. [공식 OpenAI 문서](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) | 기존 MCP 호환성을 유지한다. MCP 등록을 특정 Codex 세션의 자동 실행으로 표현하지 않는다. |
| Claude Code | 원격 HTTP MCP와 인증 헤더 등록을 지원한다. [공식 문서](https://code.claude.com/docs/en/mcp) | 같은 Deuce 서버를 사용하되 최초 안내는 선택한 앱 하나에 맞춰 보여준다. Claude의 다른 앱까지 지원 범위를 확대해 주장하지 않는다. |

경쟁 제품의 플랜·관리자 정책·그룹/채널 지원 범위는 서로 다르다. 위 표는 흐름의
참고이며, Teams 또는 Slack의 모든 AI가 모든 대화에서 작동한다는 의미가 아니다.

## 현재 Deuce와의 차이

| 영역 | main에서 확인한 구현 | 이번 요구를 위한 추가 개발 |
|---|---|---|
| 초대 입구 | `ChatView.tsx`의 AI 연결 → `AgentSettings.tsx` → 내 에이전트 설정 | 기본 AI를 바로 초대하는 헤더 버튼, 참여 배지·시스템 알림 |
| 최초 연결 | `MyAgentsSettings.tsx`에서 키 발급 후 `AgentConnectionSetup.tsx`에 Codex·Claude 안내 동시 노출 | AI 선택 → 선택한 앱 안내 → 실제 연결 확인 → 원래 방 복귀 |
| 방 접근 | `AgentScopeSchema`는 `CHANNELS`/`ALL`. 개인 AI는 해당 범위의 기존·새 방에 자동 접근하고 방별 제외 | 새 연결의 기본을 **초대한 방만**으로 설계. DM 하나 초대하려고 모든 대화 권한을 주지 않음 |
| 참여 판정 | `apps/server/src/domain/agents.ts`가 소유자 멤버십·범위·제외를 모든 요청에 적용 | 명시적 방별 초대 권한을 같은 판정에 포함. 기존 넓은 범위 연결·채널 키는 보존하고 별도 전환 안내 |
| 실행 상태 | 등록·만료·회수·참여 표시. 실행기 상태/작업 수신 확인 필드는 없음 | 접근 가능과 응답 가능을 별개로 추적. 초대와 요청의 실패·오프라인을 표시 |
| 실제 응답 | 외부 AI에 사용자가 요청하면 MCP 도구 호출 | 초대/멘션을 실행 중인 AI로 전달하고 결과를 해당 방에 게시하는 실행 경로 |
| 모바일 | 고정 폭 대화 목록과 채팅의 나란한 배치, 반응형 전환 없음 | 목록↔채팅 전환, 헤더에 노출된 AI 초대, 터치 가능한 버튼·하단 입력창 |

현재 권한 근거: [ADR 011](../adr/011-personal-agent-participation.md).
기존 사용법은 [AI 연결 안내](../ai-connections.md)를 따른다. 이 문서는 새 흐름을 제안하며
기존 API·스키마·배포 상태를 바꾸지 않는다.

## 제안하는 사용 흐름

1. **최초 한 번**: 내 AI(Codex 또는 Claude Code)를 연결하고 기본 AI로 정한다.
   아직 연결하지 않은 사용자가 초대를 누르면 짧은 연결 안내를 열고 원래 방을 기억한다.
2. **대화 중**: 헤더의 `AI 초대`를 한 번 누른다. 버튼 근처에 초대할 AI와
   `이 방의 대화·자료 공유`를 미리 표시한다. 연결된 기본 AI에는 매번 확인 모달을 요구하지 않는다.
3. **초대 성공**: `도윤님이 Codex를 초대했습니다`라는 시스템 메시지와 AI 참여 배지를
   모든 참여자에게 표시한다. 기존 대화·첨부와 이후 메시지에 대한 접근 범위가 이 방임을 알린다.
4. **함께 대화**: `@Codex 지금까지 요약해줘`처럼 요청한다. 빠른 요청 버튼은
   메시지를 작성할 수 있게 돕는다. 초대만으로 유료 조사를 시작하지 않는 것을 초기 제안으로 둔다.
5. **종료**: 참여 배지에서 `이 방에서 내보내기`. 다음 읽기·검색·첨부·게시를 차단한다.
   이미 게시된 AI 메시지는 대화 기록으로 남는다. 다른 방과 전역 연결은 유지한다.

초대 후 누구의 요청에 답할지는 초기 제안에서 **방의 사람 참여자**로 둔다. 소유자가
최초 연결 때 이를 알 수 있어야 하며, AI끼리의 멘션은 자동 실행하지 않아 반복 호출을 막는다.
소유자만 요청하도록 할지, 사용량 제한을 어떻게 둘지는 실제 실행기 설계 전에 확정한다.

## 우선순위와 완료 기준

| 순서 | 개발 범위 | 완료를 확인할 방법 |
|---|---|---|
| P0-1 | 초대한 방에만 접근하는 권한, 기본 AI, 초대/퇴장 API | 두 계정·DM/그룹/채널에서 초대·내보내기 확인. 다른 방 목록/검색/본문/첨부/게시 거부. 소유자가 방을 떠난 경우도 차단. 기존 키 권한 회귀 없음 |
| P0-2 | 헤더 한 번 초대, 모두에게 보이는 참여 표시, 처음 연결 시 복귀 | 연결 완료 사용자가 모달 없이 1회 클릭으로 초대. 중복 클릭/통신 실패에 중복 참여·성공 알림 없음. 처음 연결 취소 시 초안 보존 |
| P0-3 | 실제 연결 확인과 실행기 수신·응답 상태 | 키 발급만으로 연결 성공 표시 금지. 방을 구분한 실제 요청/수신/답변 확인. 오프라인·시간 초과·회수 중 응답을 처리 |
| P0-4 | 모바일의 같은 흐름 | 360px 폭에서 가로 넘침 없이 목록↔채팅, 초대, 요청, 내보내기. 입력 도중 초대·화면 전환에도 초안 보존 |
| P1 | 다른 AI로 기본값 변경, 자료 근거·원문 이동, 실패 요청 재시도 | 같은 방·같은 질문의 중복 답변 방지, AI 이름/소유자/근거 확인 |
| 보류 | 영상통화, 앱스토어 출시, 모든 메시지 자동 응답, AI 간 자율 대화 | P0 실제 두 사용자 검증 후 별도 선정 |

**한 번 클릭의 완료 기준은 ‘초대 버튼이 생김’이 아니라**, 기본 AI가 그 방에서 실제
요청을 받고 답할 수 있으며 상대 사용자에게 참여가 보이는 것이다. MCP 접근 허용만
완료한 단계는 중간 단계로 표기한다.

## 구현 전에 풀어야 할 실행 문제

현재 Deuce MCP는 AI가 호출하는 도구 서버다. 단순한 설정 복사·방 권한 토글로는
꺼진 외부 AI 세션을 깨울 수 없다. 현재 코드와 위 문서를 함께 읽은 **구현상의 판단**이다.
외부 앱을 여는 범용 딥링크가 검증된 것처럼 버튼에 넣지 않는다.

다음 개발의 첫 기술 검증은 **실행 중인 개인 AI에 방 ID가 포함된 요청을 전달하고,
그 방에 한 번만 답하도록 하는 작은 종단간 실험**이다. 로컬 실행기와 서버 실행기 중
어느 쪽을 쓸지는 연결 자격 증명·사용량 부담·PC 꺼짐 때 동작을 비교한 뒤 결정한다.
초기에는 개인 AI라는 방향에 맞춰 로컬 실행기를 우선 검토한다. 모바일 단독/PC가 꺼진
상황까지 응답하려면 항상 실행되는 경로가 추가로 필요하다. MCP OAuth 도입은 최초 등록을
쉽게 하는 별도 작업이며 자동 응답 문제를 해결하지는 않는다.

현재 TypeScript·Fastify·Socket.IO·Prisma 및 MCP SDK를 먼저 검토한다. 이번 요구만으로
Go나 별도 큐 제품을 추가할 이유는 확인되지 않았다. 실행기 선정 전 임의 재시도·큐·새 인증
프로토콜을 구현하지 않는다. 요청 ID와 방 ID로 초대→수신→도구→게시를 기존 진단 하네스에
연결하고, 로그에는 토큰이나 대화 본문을 기본으로 남기지 않는다.

## 눌러볼 시안과 다음 확인

[PC·모바일 시안](ai-invite-prototype.html)은 외부 의존성이 없는 단일 HTML이다.
파일을 브라우저로 열면 된다. 상단에서 연결 완료/처음 연결/AI 오프라인/초대 실패를
선택해 흐름을 바꿀 수 있다. 대화·AI 응답·연결 확인은 모두 메모리 안의 예시이며
서버 요청·실제 인증·모델 실행·비용 발생·실사용자 게시가 없다. 새로고침하면 초기화된다.

첫 체험에서는 우측 위 `AI 초대` → `지금까지 요약` → 전송을 누르고, 다른 방으로
옮겼을 때 초대가 전파되지 않는지 확인한다. 모바일은 목록으로 돌아가기와 입력창을 확인한다.
이후 사용자 3~5명에게 같은 과제를 제시해 초대 발견 시간, 최초 연결 이탈, 권한 범위 이해,
오프라인 상태 이해를 관찰한다. **아직 시행하지 않은 조사 계획**이다.

다음 구현 순서는 방별 초대 권한 및 실행기 검증 → 연결 확인 → 실제 초대 UI와 모바일
레이아웃 → 두 사용자 시험이다. 운영 배포와 모바일 패키징은 그 다음 단계다.
