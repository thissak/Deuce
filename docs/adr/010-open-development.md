# ADR 010 — 공개 개발과 운영 인스턴스 분리

상태: 채택, 2026-09-08 (저장소 공개 전환은 별도 진행)

## 배경

사람과 각자의 AI가 함께 쓰는 채팅 앱을 공개 개발한다. 기존 운영 VM은 유지관리자
계정에서 다른 서비스와 함께 실행 중이며 실제 사용자와 대화가 있다. 소스 기여를 위해
운영 VM 권한이나 운영 로그인 설정을 공유할 필요가 없어야 한다.

## 결정

- 소스·문서에 Apache-2.0을 적용하고 외부 의존성의 고지를 유지한다.
- 기존 VM은 초대형 테스트 인스턴스로 유지한다. 비용·접근·데이터는 운영자가 관리한다.
  공개 개발을 위해 VM·IAM·결제 계정을 변경하지 않는다.
- 외부 기여는 로컬 PostgreSQL과 모의 Google 응답을 사용하는 테스트로 검증한다.
  개인 글로벌 AI 설정·스킬 설치를 기여의 필수 조건으로 삼지 않는다.
- CI는 GitHub 호스팅 러너, 읽기 권한, 고정한 Action 커밋을 사용한다. Node 24/26에서
  테스트·타입 검사·소스 빌드, Gitleaks 기본 규칙과 Deuce 키 규칙으로 이력을 검사한다.
  운영 키·VM 러너·자동 배포는 연결하지 않는다.
- 자체 서버용 데스크톱은 `DEUCE_APP_ORIGIN`으로 HTTPS 원점을 빌드 시 고정한다.
  패키징 설정은 빌드된 원점에서 업데이트 피드를 만들며 불일치를 거부한다.
  Google Desktop OAuth 프로젝트 제한과 개인 Mac 인증서 고정값을 제거한다.
- 운영 예제는 운영자 자신의 도메인·버킷·프로젝트를 설정하도록 한다. 기존 VM에 설치된
  설정과 스크립트는 이 작업으로 바뀌지 않는다.
- 환경 파일·키·운영 증빙은 공개 후보에서 제외한다. 공개 문서의 운영 식별자는 예시로
  바꾸고 원본은 로컬 `.private/`에 보존한다. 기존 Git 이력은 임의로 재작성하지 않는다.

## 범위와 결과

공식 앱과 자체 서버용 앱의 동시 설치, 앱 내 서버 선택, 서버 간 연합, 일반 공개 회원가입,
다중 프로세스 배포는 후속 범위다. Mac·Windows 새 설치 파일을 이번 작업으로 배포하지 않는다.

전체 코드 이력의 비밀정보 검사와 별도로, 기존 이력에 개인 경로·이메일·운영 리소스명이
남아 있음을 공개 전 검토한다. 현재 소스만 담은 이력 없는 공개 후보를 별도로 준비한다.
이는 기존 저장소를 재작성하거나 삭제하지 않는다.
