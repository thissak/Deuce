# ADR 013: 기존 AI 기능 철회와 사용 흐름 재설계

## Status

Accepted (2026-09-11), 로컬 구현·검증 완료, 미배포. 감독의 “코드를 걷어내고 다시 계획부터”와 진행 지시에 따른다.
ADR 007의 AI 부분, ADR 008·011·012의 실행 중 기능 결정을 대체한다. ADR 007의 사람 채널 기능은 유지한다.

## Context

봇 이름·방 접근 권한·PC 실행기 상태가 현재 대화 세션 연결처럼 보였다.
기존 설계를 계속 확장하기보다 실제 연결 대상과 다른 참여자의 사용 흐름을 먼저 결정해야 한다.

## Decision

- AI UI·관리/요청 API·MCP·Socket.IO 실행기 네임스페이스·데스크톱 실행기 및 전용 패키지를 제거한다.
- 기존 migration을 수정하지 않고 새 migration으로 키 회수, 기본 AI 해제, RUNNING 요청 실패 처리를 수행한다.
- 사용자·메시지·연결·권한·실행 기록 테이블은 보존한다. 과거 AI 작성자 표시와 시스템 메시지도 유지한다.
- 일반 사용자 인증의 `isAgent` 차단과 과거 진단 분류는 호환성·접근 통제를 위해 유지한다.
- 사람 멘션만 새 멘션 대상으로 허용한다. 구버전 `clientMessageId`의 중복 메시지 방지 계약은 유지한다.
- [새 계획](../design/2026-09-11-ai-restart-plan.md)의 사용자 흐름 선택과 기술 실험 후 신규 모델을 결정한다.

## Consequences

기존 AI 클라이언트는 새 서버에서 동작하지 않는다. 운영 변경에는 서버 중지 후 migration과 웹·데스크톱 동시 배포가 필요하다.
키 회수는 코드 롤백으로 취소되지 않는다. 데이터 삭제를 피하면서 접근·실행 경로를 철회할 수 있으나,
보관용 DB 모델과 과거 기록 표시가 남는 것은 의도적이다. 검증 및 적용 절차는 [#18](../issues/18-reset-ai-feature.md)에 기록한다.
