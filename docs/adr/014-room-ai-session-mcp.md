# ADR 014: 사용 중인 AI 세션을 방 하나에 MCP로 연결

## Status

Accepted (2026-10-23). [ADR 013](013-retire-ai-and-replan.md)의 MCP 제거 결정 중 방 단위 읽기·쓰기만 되살린다.
초대·요청 버튼·PC 실행기·개인 범위 키는 계속 제거 상태다.

## Context

감독의 목표는 “지금 쓰는 세션을 붙이는 것”이다([재설계 계획](../design/2026-09-11-ai-restart-plan.md)).
다른 프로젝트의 Claude Code 세션이 긴 작업 결과와 승인 질문을 감독에게 보내고, 감독이 Deuce에서 답하면
그 세션이 답을 읽고 이어가야 한다. MCP는 세션이 직접 호출하는 도구라서 새 실행을 만들지 않고
**같은 세션**이 읽고 쓴다. 쉬고 있는 세션을 Deuce가 깨우는 기능은 아니다.

#18 이전 구현(`da3d0e6`)의 키·권한·원격 MCP는 리뷰와 운영 검증을 거쳤다. DB 모델(`AgentConnection`,
`User.isAgent`)도 보존되어 있어 마이그레이션이 필요 없다.

## Decision

- 방 멤버가 그룹·채널 방 메뉴의 **AI 세션 연결**에서 AI 이름을 정해 방 전용 키를 발급한다.
  1:1 대화에는 연결하지 않는다. 키는 그 방 하나에만 쓰고 개인 범위 키는 발급하지 않는다.
- 키는 `deuce_` + 256비트 무작위 값이다. SHA-256만 저장하고 원문은 발급 응답에서 한 번만 준다.
  90일 뒤 만료되고 소유자가 해제하면 즉시 회수한다. 요청마다 회수·만료·소유자 허용 목록·소유자의 방 멤버십을 다시 확인한다.
- 연결과 해제는 방에 시스템 메시지로 남긴다. AI 글에는 기존 AI 표시가 붙는다.
- 서버의 원격 Streamable HTTP MCP(`/mcp`)만 제공한다. 사용자는 `claude mcp add --transport http` 또는 Codex 설정
  한 줄로 연결하고 PC에 별도 패키지를 설치하지 않는다. 도구는 `get_conversation`, `read_messages`(`after` 이후 새 글),
  `post_message` 세 개다.
- AI API(`/api/agent/*`)는 Bearer 키만 받고 사람 세션 API와 섞지 않는다. 다른 사용자 이메일을 주지 않는다.
  AI당 분당 120회, MCP 본문 64 KiB, 글 4,000자로 제한한다. 오류는 서버가 정한 짧은 코드만 돌려준다.
- 자동 감시·자동 응답·쓰기 자동 재시도는 하지 않는다.

## Consequences

- 감독과 팀원은 각자 사용 중인 Claude Code·Codex 세션을 방에 붙여 작업 보고와 질문을 받을 수 있다.
  AI 글도 기존 새 메시지 알림을 탄다.
- 키는 사용자 MCP 설정(`~/.claude.json` 등)에 저장된다. 노출되면 방에서 연결을 해제하고 새로 발급한다.
- 같은 세션 맥락에서 나온 답이 방에 게시되므로, 무엇을 공유할지는 세션 소유자의 요청과 MCP 도구 안내에 따른다.
- Deuce가 쉬고 있는 세션에 질문을 밀어 넣는 양방향 연결은 계획의 다음 단계로 남는다.
