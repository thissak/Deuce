# ADR 002: 프로젝트 사이트 임베드는 iframe 방식만 제공

- 상태: Accepted (2026-08-29)

## 맥락

골든랩은 프로젝트마다 프로젝트 사이트를 만들며, 리뷰게이트
(EtaxbookGateLab)는 채널 채팅을 자체 구현한 전례가 있다(그쪽 ADR 058/060 —
평면 인용·읽음 커서 등 Deuce와 동일 사상). 프로젝트마다 채팅을 다시 만드는
중복을 없애기 위해 Deuce를 중앙 채팅 서비스로 두고, 각 프로젝트 사이트가
무개발로 붙일 수 있는 모듈 형태가 필요하다. 후보는 (1) iframe 임베드,
(2) React 컴포넌트 패키지 배포, (3) 두 가지 병행.

## 결정

**iframe 임베드만 제공한다.**

- URL 계약: `https://deuce.goldenlabs.dev/embed/{embed_key}` — 크롬 없는
  단일 대화방 패널. 임베드 키는 그룹 대화방 설정에서 발급·회수
- 삽입: 문서화된 iframe 스니펫 또는 `embed.js` 로더 한 줄
- 인증: 내부 사이트가 전부 `*.goldenlabs.dev` 소속이라 iframe은 same-site —
  Deuce 세션 쿠키가 그대로 동작. 호스트 사이트 인증 코드 0줄
- postMessage 브리지는 안 읽음 개수·패널 높이만 (리뷰게이트 뷰어 브리지
  `useViewerBridge` 패턴 참조)
- 권한 경계: 임베드 키는 표시할 방의 지정자일 뿐, 접근 권한은 항상 로그인
  세션 + 대화방 멤버십으로 검사

## 기각된 대안

- **React 컴포넌트 패키지**: 호스트를 React로 제한하고 버전 배포·의존성
  관리 부담이 생긴다. 호스트 스택이 통일돼 있지 않은 상황에서 YAGNI.
- **병행 제공**: 유지보수 표면만 두 배가 된다.

리뷰게이트가 전자책 뷰어를 iframe + postMessage로 싣는 패턴을 이미
핵심 아키텍처로 검증했으므로, 같은 요령을 재사용하는 것이 가장 싸고
확실하다.

## 결과

- 프로젝트 사이트는 프레임워크 불문 스니펫 한 줄로 채팅을 얻는다.
- 리뷰게이트 기존 채널 기능의 Deuce 대체 여부는 해당 프로젝트에서 별도
  결정한다 (이 프로젝트 범위 밖).
