# AI 기능 제거·메시지 액션 바 0.2.4 배포

## 결과

- 구현 기준 커밋: `7a9ea6f5ad8e9a6eec6db5e39a7a2a5928f4f4ac`
- 운영 웹 릴리스: `20260911-02`
- 데스크톱: Mac arm64/x64·Windows x64 `0.2.4`
- AI 초대·설정·요청 UI, 서버 AI API·MCP·실행기 소켓, 데스크톱 PC 실행기와 전용 패키지를 제거했다.
- 사람 멘션과 과거 AI 메시지·작성자 표시는 기록으로 유지했다.
- 메시지 액션 바는 GateLab과 같이 말풍선 위 경계에 두고 내 메시지는 오른쪽, 상대 메시지는 왼쪽에 맞췄다.

## 검증

- 로컬: 웹 155·서버 79·데스크톱 10개, 총 244개 테스트와 전체 타입 검사·빌드 통과.
- 배포 후보 333개 소스 파일을 커밋과 대조했고 운영 복제 DB에서 migration 8→9와 서버 79개 테스트를 통과했다.
- 구 AI `/api/agents`, `/api/agent/messages`, `/mcp`는 404이며 구 실행기 Socket.IO namespace도 등록되지 않는다.
- Mac x64 공증 ID `304d7a06-7fad-418f-b88f-76e6eb7675e4`, arm64 공증 ID `537a9305-f6ca-4ef0-b881-3c86a281e701`이 Accepted 상태다. 두 앱의 Developer ID 서명·staple·Gatekeeper와 두 DMG를 확인했다.
- 공개 웹·데스크톱 파일 58개 전체 SHA-256과 health·인증·제거 경로를 포함한 HTTP 점검 8개를 확인했다.
- 설치 Mac은 업데이트 피드로 0.2.3→0.2.4 교체·재실행됐다. AI 제어가 없고 상대 메시지 액션 바가 본문 위 왼쪽에 표시되는 화면을 확인했다.

## 운영 데이터

배포 직전 백업을 성공시킨 뒤 구 서버를 중지하고 `20260911080000_retire_ai_feature`를 적용했다.

| 항목 | 적용 전 | 적용 후 |
|---|---:|---:|
| 연결 기록 | 7 | 7 |
| 활성 연결 | 7 | 0 |
| 기본 AI | 1 | 0 |
| RUNNING 요청 | 0 | 0 |
| 메시지 | 95 | 95 |

메시지·grant·exclusion·token·완료 실행 기록의 지문도 전후 일치했다. migration은 연결 키를 회수하고 기본 AI를 해제하며 진행 중 실행만 실패 상태로 정리한다. 테이블과 과거 AI 대화는 삭제하지 않는다.

## 화면 잔상 진단

배포 직후 설치 앱 화면에 예전 AI 제어가 한 번 남았다. 운영 소스와 번들에는 해당 문자열이 없었고 제거 경로도 이미 404였다. 실행 중이던 0.2.3 Electron 렌더러가 이전 화면을 메모리에 유지한 상태였으며 **Deuce → 보기 → 새로고침**으로 새 웹 번들을 읽자 제어가 사라졌다. 이후 자동 업데이트로 앱 자체도 0.2.4로 교체했다.

## 복구 경계

- 서버 코드는 `/opt/deuce/releases/20260911-01`, 데스크톱 공개 디렉터리는 `0.2.3`을 이전 버전으로 보존한다.
- 코드 링크와 다운로드 링크는 원자적으로 이전 버전으로 돌릴 수 있다.
- 이번 migration의 키 회수·기본 AI 해제는 코드 롤백으로 되돌아가지 않는다. AI 기능 복구가 필요하면 운영 백업 복원 또는 별도 순방향 migration 판단이 필요하다.
- 소스 압축본, 데스크톱 산출물, `DEPLOYMENT.json`·`VERIFICATION.json`·`ACTIVATION.json`·`PUBLIC.json`은 비공개 릴리스 저장소의 `releases/20260911-02/`에 보존했다.
- 사용자 작업 중인 `docs/design/2026-09-08-persistent-codex-sessions-plan.md`는 릴리스 소스와 커밋에서 제외했다.
