## 검증 결과와 즉시 할 일

1. **먼저 테스트 타입 오류를 고친다.** 웹 테스트 19파일·128개는 통과했지만
   `pnpm --filter @deuce/web build`는 새 회귀 테스트의 Testing Library
   `getByRole(..., { name, exact: true })` 3곳에서 TS2769로 실패했다.
   Playwright 옵션과 혼동해 넣은 `exact`다. Testing Library의 문자열 `name`
   매칭에 불필요하므로 제거 후 점프 테스트·타입 검사·빌드를 재검증한다.
2. **Chrome 플러그인으로 수정 동기화부터 다시 확인한다.** Codex의 임시
   Playwright 스크립트가 같은 계정의 두 번째 탭을 열고 메시지를 수정한 뒤,
   상대 탭에서 `getByText(edited, {exact:true})` 대기 중 8초 타임아웃됐다.
   원래 탭의 메시지 수정 성공은 스크린샷으로 확인했다. 상대 탭의 DOM·소켓
   상태는 확보하지 못했으므로 **실시간 제품 버그라고 확정하면 안 된다**.
   선택자 문제인지 소켓 준비/이벤트 문제인지 직접 확인한다.
3. 메시지 생성·답장·수정·삭제·반응·고정/해제, 파일 캡션·공유 탭·다운로드
   바이트, 한국어 검색·활동 점프, 스크롤 3종을 직접 검증한다. 스크립트는
   수정 동기화 단계에서 멈췄으므로 뒤 단계가 통과했다고 기록하지 않는다.
4. 두 실제 계정이 필요한 unread·타인 프레즌스·알림 항목은 분리해 관리한다.
   독립 테스트 사용자 세션으로 자동 검증하더라도 실제 OAuth 두 계정 검증과

5. 발견 문제는 재현 → 원인 → 공식 자료 조사 → 최소 수정 → 회귀 검증으로
   처리하고 update-docs로 실제 결과를 기록한다. 계획 ⑤ Electron은 브라우저
   검증 완료 전 시작하지 않는다.

### 발견한 결함과 수정 (모두 회귀 테스트 포함, 실 Chrome 재확인)

1. `Timeline.tsx` 과거 로드 보정 무효 — `await fetchNextPage()` 뒤 rAF 보정이
   react-query v5 setTimeout 배치 알림보다 먼저 돌아 높이 차 0. 브라우저 계측
   로그: 클릭 후 DOM 변경(53행) 시점의 scrollTop 0, 이후 scroll 이벤트 없음.
   → 페이지 수 키 `useLayoutEffect`에서 커밋 직후 보정. `timeline.test.tsx`에
   rAF 동기 실행 순서를 재현한 테스트 추가(구 코드 실패 확인).
2. `cache.ts` 인용 답장 미갱신 — 탭 A가 원본 삭제 시 탭 A 인용은 "삭제된
   메시지입니다"(자기 mutation의 재조회)인데 탭 B 인용은 원문 그대로. →
   `replaceMessage`가 `replyTo.body/deleted`도 갱신. 수정 후 탭 B 인용이
   "스크롤 검증 62 수정본"으로 즉시 바뀜 확인.
3. `Composer.tsx` 전송 대기 중 입력 소실 — Enter 뒤 바로 이어 쓰면 pending 동안
   submit이 무시되고 onSuccess의 `setText('')`가 새 입력까지 지움(시드 중 10건 중
   1건만 전송되며 발견). 1차 수정(즉시 비움+실패 시 조건부 복원)은 Codex 1차 검수에서
   실패 원문 유실(P1)·업로드 잔존(P2), 2차 수정(별도 실패 슬롯)은 2차 검수에서 덮어쓰기·
   답장 대상 변경·새 초안 파일 삭제 3건이 나와 Fix-Loop Circuit Breaker로 설계를 재검토했다.
   최종 설계(Codex 동의): ①초안(텍스트·파일 칩·답장 칩)은 제출 전까지 사용자 소유, 제출

   `reset` 활용, 별도 슬롯·ref·큐 없음) ③미해결 payload가 있으면 새 전송을 받지 않는다
   (보내기 비활성, Enter 무시, 초안 작성은 가능) ④성공·실패 콜백은 초안을 건드리지 않는다

### 도구 주의 (재검증 시)

- Chrome 플러그인 `javascript_tool`로 실행한 `el.scrollTo`는 offset은 바뀌지만(2203→1903)
  같은 호출에서 등록한 scroll 리스너가 500ms 안에 호출되지 않았다(하단 추종 ref 미갱신
  → 오탐). **도구 실행 문맥에 한정된 관측**이며, 일반 Chromium에서는 API 스크롤에도
  scroll 이벤트가 발생한다(CSSOM View §13.2, Codex 독립 확인). 스크롤 검증은 휠 액션으로.
  또한 async IIFE의 반환값은 `{}`로 돌아와 폴링 결과는 스크린샷으로 확인해야 한다. 백그라운드 탭은 좌표 클릭이 포커스를 못 잡을 수
  있어 `find`→ref 클릭 또는 JS `.focus()/.click()`을 쓴다. `fetch`·`key=value`
  문자열은 차단된다.
