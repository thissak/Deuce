# 개인 AI 초대 — 0.2.0 배포 결과

2026-09-08 운영 웹/API와 데스크톱 0.2.0을 배포했다.
[다운로드](https://deuce.goldenlabs.dev/download)에서 새 앱을 설치하거나 기존 앱의
Deuce → 업데이트 확인 → 다운로드 → 재시작하고 설치를 사용한다.
한 번 연결한 개인 AI는 대화의 **AI 초대** 버튼으로 재사용한다.

## 리뷰와 코드

  [PR #15](https://github.com/thissak/Deuce/pull/15), 채팅 UI

- 리뷰 중 삭제 질문 원문의 실행 상태 API 노출, 오래된 계정 복구 응답,
  AI 요청 재시도의 이중 제출을 재현·수정했다. PC 실행 취소 시 하위 프로세스 종료와
  Windows CLI 실행도 보강했다.
- 운영 소스: `e372b492a4e0ac276d36db1d1d7ac6e44a930ba3`.
  main 머지 커밋 `d1f6c2c8cf08541d018535c794a1036ca07550a0`과 소스 내용이 같다.
- CI Node 24/26에서 전체 **270개**: 서버 94·웹 156·데스크톱 12·실행기 6·MCP 2,
  타입 검사·소스 빌드와 비밀 검사 통과. Windows Node 24 실행기 테스트도 통과했다.

## 운영 서버

- 기존 VM의 새 릴리스 `20260908-03`에 파일 267개의 SHA-256을 기록했다.
  기존 `20260908-02`와 비공개 DB/첨부/설정 백업을 보존했다.
- 운영 백업을 새 DB에 복원하고 **migration 4→8**을 적용했다. 원래 9개 테이블의
  모든 기존 컬럼·행을 해시로 대조해 보존을 확인했다. 당시 메시지 37개·AI 연결 3개,
  첨부 0개였다. 실제 첨부가 있는 운영 백업의 복원 검증을 의미하지 않는다.
- 별도 테스트 DB에서 VM Node 24·PostgreSQL 17의 서버 94개 테스트를 통과했다.
  UI 리뷰 수정 뒤에는 서버·공용 계약·의존성 파일이 동일함을 해시로 확인했다.
- 운영 서비스를 정지한 상태에서 다시 백업하고 migration을 적용했다. 기존 컬럼·행을
  재대조한 뒤 current 링크를 전환하고 Deuce를 시작했다. 다른 서비스는 정상 유지됐다.
- 공개 health·새 웹 자산 200, 미로그인 API/MCP 401, `.env` 404 확인.
  실제 앱의 로그인 200과 기존 대화 4개·AI 연결 3개가 유지됐다.
- 검증 시점 운영 로그에서 HTTP 5xx·AI 실행 실패·연결 키 패턴은 발견되지 않았다.

## 앱과 AI 실행

| 검증 | 결과 |
|---|---|
| Mac arm64/x64 | Developer ID 서명·Apple 공증·staple·Gatekeeper 검증 통과 |
| Windows x64 | NSIS 제작, 공개 EXE 114,135,644바이트 전체 다운로드·SHA-512 일치 |
| 업데이트 피드 | 피드 2개가 참조하는 설치 파일 5개의 크기·SHA-512 일치, 배포 파일 14개 SHA-256 검증 |
| 공개 파일 제공 | 작은 파일 전체 해시, 모든 큰 파일 Range 206·전체 크기·첫 바이트 확인 |
| 실제 Mac 업데이트 | 설치된 0.1.2가 0.2.0 감지 → 131,553,509바이트 ZIP 다운로드·해시 일치 → Squirrel 완료 → 기존 PID 종료·새 PID 자동 실행 |
| 설치 결과 | 0.2.0 버전·패키징 app.asar 일치·코드 서명, 디버깅 옵션 없는 자동 실행 확인 |
| 로그인·연결 | 기존 Google 로그인 유지. 설치된 앱의 실제 native 연결 API로 Claude를 연결하고 기존 Codex 연결을 재사용 |
| 실제 모델 | 본인만 참여하는 확인 채널의 텍스트 첨부 코드를 Codex·Claude가 각각 읽고 AI 신원으로 답변 |
| 암호화·복구 | 키 평문 없는 0600 저장 파일, 동일 계정의 두 AI가 앱 재실행 후 READY로 복구, 복구된 AI의 실제 답변 확인 |
| 운영 MCP | 새 SELECTED 연결의 인증된 대화 목록 읽기 성공, 초대하지 않은 방이 목록에서 제외됨 |

화면 이동과 자동 조작이 겹쳐 운영의 후반 검증은 현재 화면을 유지한 채 실제
preload API·서버 API를 호출했다. 연결 함수나 모델 실행을 모의하지 않았다.
버튼을 클릭하는 전체 흐름은 별도의 두 계정 Chromium에서 Codex/Claude 각각 검증했다.
운영 확인용 채널에는 본인만 참여하며 다른 사용자의 대화에 검증 메시지를 보내지 않았다.

0.1.2에는 AI 암호화 저장 기능이 없으므로, 이번 검증은 **버전 업데이트의 로그인 유지**와
**0.2.0 재실행의 AI 연결 복구**를 각각 확인한 것이다.
이미 AI가 저장된 구버전에서 새 버전으로 업데이트하는 시험은 후속 릴리스에서 수행한다.

## 남은 검증과 범위

- Windows와 Intel Mac의 실제 기기에서 설치·업데이트·CLI 로그인/실행은 미검증이다.
  Windows CI·설치 파일 다운로드, Intel 서명/공증 검증과 구분한다.
- 4시간 자동 확인 타이머는 코드 확인이며 실제 4시간 경과 시험은 수행하지 않았다.
- 다른 사용자 3~5명의 최초 CLI 설치·로그인·연결·한 번 초대 사용성 조사가 남았다.
- 응답하려면 연결한 PC와 앱/실행기가 켜져 있어야 한다. 자동 실행의 자료 범위는 최근
  메시지 50개와 작은 텍스트 첨부다. 이미지/PDF 해석·인터넷 조사·자율 감시는 후속 범위다.

## 증빙과 복구

공개 저장소에는 비밀 키·쿠키·운영 대화 원문을 포함하지 않는다.
로컬 세부 증빙은 `.private/ai-invite-release/`에 있고, VM 릴리스의
`DEPLOYMENT.json`, `VERIFICATION.json`, `ACTIVATION.json`에 파일/검증 결과를 기록했다.
업데이트 관측에는 기존 `scripts/desktop-update-observer.cjs`를 사용했다.

다운로드 링크는 이전 배포 디렉터리로 되돌릴 수 있지만 설치된 앱을 자동으로 낮추지는 않는다.
DB 변경은 되돌리지 않았다. 새 SELECTED 연결·초대 권한을 사용하는 데이터가 생성됐으므로
구버전 코드로 단순 전환하기 전에 스키마와 권한 호환성을 판단해야 한다.
