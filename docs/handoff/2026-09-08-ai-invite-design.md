# 대화 중 AI 초대 조사·시안 이관

> 이후 구현은 [실제 초대·실행기 이관](2026-09-08-ai-invite-implementation.md)에 기록했다.
> 아래는 구현 전 조사·시안 시점의 이력이다.

## 완료된 작업

- 감독이 선택한 “간단한 AI 연결”을 **현재 대화에서 기본 AI 한 번 초대**로 구체화했다.
- [공식 자료 조사와 요구사항](../design/2026-09-08-ai-invite-research.md)에 경쟁 제품의 관찰 사실, 현재 코드와의 차이, 제안·미확정 사항을 구분했다.
- [단일 HTML 시안](../design/ai-invite-prototype.html)을 만들었다. 외부 의존성 없이 파일을 브라우저에서 열면 된다. 상단의 체험 상태로 연결 완료/처음 연결/AI 오프라인/초대 실패를 전환한다.
- 실제 서버·인증·AI 호출·사용자 메시지 게시 없이 예시 데이터만 메모리에 둔다. 새로고침하면 초기화된다.

## 시안 검증

2026-09-08, Orca 내장 Chromium에서 확인했다. PC 1440×900, 모바일 폭 390×844 및
360×780이다. 브라우저의 반응형 화면 검증이며 iOS/Android 실기 검증은 아니다.

- 실제 버튼 클릭 → 추가 모달 없이 AI 참여 알림/배지 → 요약 제안 선택 → Enter 전송 → 예시 AI 답변 표시
- 다른 DM은 미초대 상태 유지, 원래 방 복귀 시 AI 참여 유지
- AI 내보내기 후 참여 표시 해제, 기존 AI 메시지 기록 유지
- 첫 연결만 안내, 연결 취소 시 초안 유지, Claude 선택·연결 완료 재현 후 원래 방 초대와 초안 유지
- 오프라인은 참여 상태와 구분, 실패 시 성공 표시 없이 오류·초안 유지
- 모바일 목록↔채팅 전환·별도 DM 초대·방별 초안 복구, 360px에서 초대/전송/모달 영역과 가로 넘침 확인
- JavaScript 구문 검사·`git diff --check` 통과, 브라우저 콘솔 메시지 없음

로컬 스크린샷: `.private/ai-invite-design/`의 `desktop-before.png`, `desktop-reply.png`,
`mobile-before.png`, `mobile-invited.png`. 공개 저장소에는 포함하지 않는다.
기존 앱 코드 변경이 없어 전체 앱 테스트를 재실행하지 않았다.

## 다음 작업

1. 현재 CHANNELS/ALL의 자동 접근을 보존하면서 새 연결에는 초대한 방만 허용하는 모델을 설계한다.
2. 실제 개인 AI 실행기가 방 ID가 포함된 요청을 받아 같은 방에 답하는 최소 실험을 한다. MCP 등록 성공을 실행 가능으로 간주하지 않는다.
3. 연결 확인, 기본 AI, 초대/퇴장 실시간 표시와 모바일 화면을 실제 앱에 구현한다.
4. 두 계정·실제 MCP/실행기로 읽기·검색·첨부·게시 권한 및 회수/오프라인 경로를 검증한다.
5. 다른 사용자에게 첫 연결과 초대 과제를 관찰한 후 운영 반영·모바일 패키징으로 진행한다.

## 미확정·제한

- 로컬/서버 실행기, 사용량 부담과 한도, 다른 참여자의 요청 허용 정책은 확정 전이다.
- 시안의 응답 가능/연결 확인/AI 답변은 재현용이다. 외부 AI 앱의 범용 자동 실행 링크는 검증하지 않았으며 넣지 않았다.
- 초대 시 이전·이후 대화·자료를 공유하는 안이다. 과거 공개 범위 및 회수 중 실행 처리는 실제 구현 시 계약으로 확정한다.
- ADR 011은 현재 구현의 계약으로 유지한다. 이번 제안은 새 아키텍처 수락이나 마이그레이션 적용이 아니다.
